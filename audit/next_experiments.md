## Этап 3. Первое реальное измерение — минимальный эксперимент, проверяющий P1

Это единственная цепочка, дающая первое измерение хвоста на настоящей модели.

**Спецификация:**

| Параметр | Значение | Обоснование |
|---|---|---|
| Модель | `deepseek-ai/DeepSeek-Prover-V2-7B` | уже скачана, токенизатор проверен на round-trip |
| Бенчмарк | miniF2F | 226 задач в test, 231 в validation |
| **Сплит** | **сэмплировать `minif2f_validation`, не test** | test был использован для отладки промпта и температур; см. P1-9. Validation становится development-сплитом, test остаётся нетронутым для confirmatory-прогона |
| Задач | 231 (весь validation) | |
| Попыток | 8 на задачу × 2 температуры (0.6, 1.0) = 3696 | как в текущем конфиге |
| Верификатор | Lean 4.34.0-rc2 + Mathlib 85e3a25e | пин уже в манифесте |
| Слои | 25 %, 50 %, 75 % глубины | из `configs/models/extract_activations.yaml` |
| Статистика | все три: `raw`, `whitened`, `innovation` | ablation нужна, а не выбор постфактум |
| Калибровка | verified-трассы непересекающегося сплита задач | реализовано в `fit_calibration` |

**Шаги и стоимость:**

| Шаг | Команда | Стоимость | Доработка |
|---|---|---|---|
| 3.1 | Сэмплинг с сохранением token IDs и сырого completion | ~4 мин A100 | **[нужна доработка]** — добавить `prompt_token_ids`, `completion_token_ids`, `raw_completion` в `Sample` |
| 3.2 | `obj lean-verify data/raw/prover-sampling/samples.jsonl --out-dir results/full/lean` | **неизвестна** — пилот дал 10 трасс за 211 с, но на игрушечных теоремах; для 3696 проофов Mathlib нужно мерить на подвыборке 50 штук прежде, чем запускать всё | нет |
| 3.3 | Извлечение активаций по сохранённым token IDs | оценить после 3.2 | **[нужна доработка]** — сейчас extraction токенизирует текст заново |
| 3.4 | `obj analyse` → P1 с разбиением по длине доказательства | минуты | **[нужна доработка]** — разбиение по `L` для P1, как уже сделано для P2 |

**Критерий завершения этапа:**
1. Не менее 200 verified и 200 refuted трасс с `L >= 4` — иначе P2 неразрешим, а P1 будет
   опираться на трассы из одного шага;
2. отчёт split-half по `xi`, показывающий, что наблюдаемая разница между verified и refuted
   **больше** расхождения между половинами тех же данных;
3. Hill-графики по всем слоям и статистикам — без них выбор `k` не аудируем.

**Критерий остановки:** если после 3.2 доля трасс с `L >= 4` окажется ниже 10 %, останавливаться и
переходить к контролируемому синтетическому эксперименту (этап 4) — на однострочных
доказательствах локализация не проверяема в принципе.

## Этап 4. Контролируемый эксперимент по глубине (для P5)

Нынешний P5 не имеет данных, а длина доказательства Lean — это наблюдаемая длина вывода, а не
заданная глубина дедукции. Нужен генератор задач PrOntoQA-типа с **управляемой** глубиной цепочки.

| Параметр | Значение |
|---|---|
| Глубины | 3…12, по 40 задач на глубину (значения уже в `SyntheticConfig`) |
| Разделять | заданную глубину, длину порождённого рассуждения и число проверяемых шагов — три разные величины |
| Оценивать | `c = theta * Fbar(tau)` как единый идентифицируемый параметр; `theta` пинить из экстремального индекса |
| Сообщать | что оценено независимо, что подогнано, и на каком сплите |

**Статус:** генератора нет. `SyntheticConfig` объявлен и не используется. **[нужна доработка]** —
это отдельная задача, не продолжение существующего кода.
