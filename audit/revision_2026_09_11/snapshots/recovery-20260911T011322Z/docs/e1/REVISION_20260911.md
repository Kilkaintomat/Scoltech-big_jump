# Recovery after the first development pilots

The 2026-09-09 campaign stopped before main acquisition. Its source snapshots, generated
attempts, labels, manifests and logs remain unchanged. Recovery creates a separate root and
new GPFS stage directories. The existing original token IDs and generation manifests are
reused; protocol files are copied byte for byte. No prompt, seed, attempt budget, temperature,
model revision, task split, truncation rule or inferential threshold is tuned from outcomes.

Corrections before main acquisition:

- Keep multiline Lean `;` / `<;>` operators and their operands in one labelled segment, including
  operators alone on a line. Source offsets retain all original lines and bytes.
- Pair all Markdown fences before selecting the last Lean block in the final answer; fenced
  non-Lean examples in reasoning must not consume the real proof. Only the trusted original
  theorem and directives are compiled, and statement substitutions remain exclusions.
- Collection gates reject the actual infrastructure error category and bind extraction source
  as well as verifier/hook source. Reusing a gathered manifest with disagreements still fails.
- Reports distinguish accounted attempts, extracted attempts and measured traces, explicitly
  stating when no usable measurements exist.
- P3 intervals count tasks actually contributing positive excesses and enforce the existing
  calibration/evaluation exceedance requirements; unrelated evaluation tasks do not support CI.
- Campaign checks are read-only. Explicit formatting is a separate development operation.
- Version-controlled recovery/dispatcher tools preserve old evidence and require passed tests,
  fresh live Lean checks and a complete real-model pilot gate before main data acquisition.

The development pilot remains inconclusive. Manual example review, statistical calibration,
transform-refitting sensitivity and the task-stratified positional null remain prerequisites
for supported scientific claims. Historical `paper_outputs/` are unchanged.
